## [Day 1] アーキテクチャの正解 (The "Agentic" Shift)

```text
【Note投稿AI「Prosper」開発記 ①】

「AIに記事を書かせる」
この言葉の解像度が低すぎる。

単にLLMに「書いて」と投げるのは素人。
玄人は **「Agentic Workflow (自律的ワークフロー)」** を組む。

1. **Planner**: 検索キーワードと構成案を策定
2. **Researcher**: Webを巡回し、事実(Fact)のみを収集
3. **Writer**: 事実に基づき執筆
4. **Editor**: 誤りと文体を修正

この「役割分担」こそが本質。
Gemini 2.5 Flash を各エージェントの脳として並列駆動させることで、
単一モデルでは不可能な「深みのある記事」が生まれる。

#AIエージェント #個人開発 #Gemini
```

## [Day 2] 検索の「質」をどう担保するか (Grounding)

```text
【Note投稿AI「Prosper」開発記 ②】

ハルシネーション（AIの嘘）をどう防ぐか？
答えは **「Search Grounding (検索による裏付け)」** の徹底にある。

Prosperの調査エージェントは、検索結果の要約を鵜呑みにしない。
Tavily APIで「信頼できる一次ソース」だけをフィルタリングし、
その本文を直接読み込み、情報の出所を明記させる。

「なんとなくそれっぽい文章」ではなく、
「出典付きの調査レポート」をまず完成させる。

この泥臭い前処理こそが、エンジニアの腕の見せ所。
#RAG #検索技術 #AI
```

## [Day 3] コストと速度のトレードオフ (Model Selection)

```text
【Note投稿AI「Prosper」開発記 ③】

なぜ最高性能の「Ultra」ではなく、あえて「Gemini 2.5 Flash」を使うのか。

理由は **「試行回数」** だ。

調査フェーズでは、数百回のWeb検索と推論を繰り返す。
ここで重厚長大なモデルを使うと、コストが死ぬし、遅すぎて実用にならない。

2.5 Flash の "圧倒的なトークン処理速度" と "安さ" があれば、
「納得いくまで何度でも調べ直させる」ことができる。

「賢いAIを1回使う」より、「速いAIを100回働かせる」。
これが2026年の最適解だ。
#MLOps #コスト最適化 #エンジニア
```

## [Day 4] 画像生成の文脈理解 (Context-Aware Art)

```text
【Note投稿AI「Prosper」開発記 ④】

記事のアイキャッチ画像。
「ロボットの絵」みたいなフリー素材、もう見飽きましたよね。

Prosperの画像生成モジュールは、記事の **「感情分析(Sentiment Analysis)」** から入る。

・記事が「希望」について書かれているか？
・それとも「警鐘」を鳴らしているか？

その感情パラメータを読み取ってから、Flux.1 にプロンプトを渡す。
だから、文章の熱量と画像のトーンが完全にシンクロする。

「ただの挿絵」じゃない。「演出」まで自動化する。
#画像生成AI #Flux1 #クリエイティブ
```
